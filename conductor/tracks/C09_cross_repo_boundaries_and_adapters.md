## Objective

Define typed interchange with related repositories without hard coupling or copying whole codebases.

## Application scope clarification — 22 November 2026

VOP demonstrates both value of perspective and value of heterogeneity. It owns
cases, evidence, assumptions, interpretation and tutorial material. VOIAGE is
the implementation home for reusable operational VOP/VOH/VOI methods and their
contracts, backends and bindings. This clarification uses C09's existing
dependency order and leaves all implementation acceptance boxes unchanged.

Current source-inspected provider entry points, at
`11a2bc8685f71c2ff351def742d439c28373cd46`, are
[`voiage.methods.perspective.value_of_perspective`](https://github.com/edithatogo/voiage/blob/11a2bc8685f71c2ff351def742d439c28373cd46/voiage/methods/perspective.py)

existing VOP output was generated by that revision.

### Bounded adoption sequence

- [ ] Inventory one existing perspective case and one heterogeneity case;
  distinguish reusable method logic from application construction/valuation.
  Preserve the original source, output identities and reference roles.
- [ ] Define independently calculated cases: one where changing evaluative
  perspective changes the preferred strategy, and one where prespecified
  subgroup-specific decisions improve on a single common strategy. State
  weights, population basis, units and the exact comparison in each case.
- [ ] Select the actual compatible VOIAGE package/artifact and public contract;
  preserve strategy, uncertainty-draw, perspective and subgroup pairing. Propose
  missing generic behaviour upstream rather than filling gaps with an
  unlabelled local production replacement.
- [ ] Execute each case through the installed provider, compare the independent
  result, record failures and qualify only the admitted method/profile. Local
  dependency presence or an API name does not prove native dispatch or parity.
- [ ] Adopt the accepted version in one application case at a time. Retain prior
  example versions and explain any change in semantics, estimates or decisions.
  Recheck affected examples before adopting each successive provider version.
- [ ] If a case adds a strategic game, link its UOGTO/Paignia intake and compose
  the supported game method through an optional adapter. Generic solvers belong
  in Paignia; the application defines payoffs and Voiage evaluates information
  value. Do not introduce a circular provider dependency.

These are pending refinements within C09, not a second track or a replacement
for C01/C08 qualification. The existing canonical manifest and local track
state remain authoritative. A documentation-only boundary clarification cannot
mark provider adoption or empirical validity complete.
